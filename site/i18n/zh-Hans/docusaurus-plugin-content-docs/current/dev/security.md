# 安全模型

本页阐述 Slurm Portal 的安全边界、各主体的权限范围以及每一道边界上的防护机制。如需报告安全漏洞，请参阅 [SECURITY.md](https://github.com/TING-HiuYu/SlurmPortal/blob/main/SECURITY.md)。

## 信任边界 {#trust-boundaries}

| 边界 | 跨越主体 | 防护机制 |
| --- | --- | --- |
| 浏览器 → 门户主服务 | 普通用户与管理员 | 域名可前置 Cloudflare Access，随后校验门户签发的 HS256 会话令牌 |
| 机器节点 → 门户主服务 | Slave 与 Web 访问网关 | 仅限同步主机名（或独立 mTLS 端口），校验客户端证书并由 WAF 拦截无证书请求 |
| 浏览器 → Web 访问网关 | 已登录用户 | 主服务签发的 Ed25519 票据（有效期 5 分钟），严格绑定用户、集群与操作范围 |
| Web 访问网关 → 登录节点 `sshd` | 代表用户的网关 | 为浏览器端生成的临时公钥签发的 5 分钟有效 SSH 用户证书 |
| 用户终端 → 集群登录节点 | 科研与工程用户 | 用户持有的门户 CA 签发的 30 天 SSH 证书，由 `sshd` 对照本地 KRL 吊销列表校验 |

在 Cloudflare 部署下，浏览器主机名与同步主机名由 `deploy/worker/edge.js` 严格隔离：

- 除同步主机名外，任何域名均拒绝访问 `/sync/*`；
- 同步主机名除 `/sync/*` 与 `/healthz` 外不提供任何其他路由；
- 客户端证书仅在同步主机名上被采信。

## 用户认证与会话安全 {#users}

### 登录认证 {#signing-in}

- **本地密码：** 使用恒定时间算法校验 Argon2id 哈希；对不存在的用户名执行耗时一致的伪校验（`password.VerifyDummy`）以防枚举用户名。15 分钟内连续失败 5 次即锁定该键。强制要求 HTTPS。
- **GitHub（OAuth）：** 按连接器的有序规则（所有人、邮箱/用户名通配符或 GitHub 组织成员）判定是否允许登录及新账号归属的用户组与角色；仅采信 GitHub 已验证的主邮箱。
- **Cloudflare Access：** 对照团队发布的公钥与应用 AUD 标签验证 Access JWT 签名。

### 会话令牌 {#sessions}

所有登录方式统一签发带有效期的 HS256 会话令牌。退出登录与刷新令牌都会吊销旧令牌 ID；签名密钥支持通过 `JWT_KEYS` / `JWT_ACTIVE_KID` 平滑轮换。

### 密码哈希 {#passwords}

- 数据库仅存储单向哈希：门户登录使用 Argon2id，OpenLDAP 使用 SHA-512 crypt。
- 明文密码仅在设置密码当次请求的内存中短暂存在。
- v1 版本遗留的可逆加密密码已在迁移 `0015` 中彻底移除。

### 密码重置验证码 {#reset-codes}

重置验证码为通过邮件发送的 6 位数字，服务端仅保存其 HMAC 摘要；有效期 10 分钟，重发间隔 1 分钟，输错 5 次即作废。

## 权限与防提权 {#permissions}

- **所有路由强制声明权限：** 遇到未声明权限的路由时，路由器在启动阶段直接拒绝运行。
- **角色授予 `(object, action)` 权限对：** 服务端在每次请求时实时校验角色权限，前端菜单隐藏仅用于交互体验。
- **角色等级阻止越权提权：** 每个角色具有数值等级（`sort`，越小越高，`1` 为超级管理员）。任何人不得创建、修改或删除等级不低于自己的用户或角色，也不得授予自己未持有的权限。
- **禁用账号同步吊销证书：** 禁用或删除用户时，在同一次原子批处理中自动吊销其所有有效证书。

## 机器身份与同步防护 {#machines}

- **证书指纹白名单：** 每个 slave 与网关的客户端证书均按 SHA-256 指纹注册，并绑定至唯一的集群或网关 ID；请求体中自称的身份一律忽略。
- **Slave 安全防线（Guard）：** 若单次同步计划删除超过 `limits.max-user-deletions` 名用户或移除已受信的 SSH CA，slave 会拒绝执行同步，防止错误快照锁死整个集群；非主服务托管的 LDAP 条目保持原样不动。
- **不可变信任世代：** 信任文件写入按内容哈希命名的不可变目录，再原子切换 `current` 符号链接，异常时可瞬间回滚。
- **观察者隔离 Slurm 密钥：** 高权限的 Slurm JWT 密钥始终保留在控制节点的 `slurm-notify-observer` 内，仅向通过 mTLS 认证的 slave 提供只读的作业与节点详情查询。

## 密钥与机密存储 {#keys-and-secrets}

| 密钥名称 | 存储位置 | 保护对象 |
| --- | --- | --- |
| `PKI_MASTER_KEY` | Worker 密钥 / 主服务 `.env` | 使用 AES-256-GCM 加密数据库中的 CA 私钥、SMTP 密码与 OAuth 密钥（`internal/secretbox`，按用途派生子密钥） |
| `JWT_KEYS` | Worker 密钥 / 主服务 `.env` | 会话令牌签名与重置验证码 HMAC |
| `PLUGIN_WEB_ACCESS_TICKET_KEY` | Worker 密钥 / 主服务 `.env` | 签发网关票据（网关侧仅持有对应公钥） |
| Slave / 网关客户端私钥 | 各机器本地文件（权限 `0600`） | 机器身份认证（主服务仅保存证书指纹） |
| CA 私钥 | 数据库加密列 | 永不离开主服务；slave 与网关仅获取公钥 |

包含敏感凭据的配置文件权限必须为 `0600` 或更严格，否则 slave、网关与生命周期钩子将拒绝启动。

## 审计日志 {#audit}

- **记录每一次状态变更：** 包括被拒绝（`401`/`403`）与执行失败的变更请求，完整记录操作者、动作、目标、结果与请求 ID。
- **SHA-256 哈希链防篡改：** `GET /api/v2/audit/verify` 遍历整条哈希链并报告首条链接断裂或哈希不匹配的记录。
- **容量上限控制：** 通过 `AUDIT_MAX_RECORDS` 限制最大记录数，超出后新记录自动替换最旧记录，校验从当前保留的最早记录开始。
- **高频机器上报降噪：** 周期性机器状态上报仅在失败时写入审计日志。

## HTTP 安全加固 {#http-hardening}

- **安全响应头：** 所有 API 响应均附带 `nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`Cache-Control: no-store` 与全拒绝 CSP。
- **按 IP 限流：** 基于连接或受信任代理头提取的客户端 IP 执行令牌桶限流。
- **严格 CORS：** 仅放行显式配置的源地址。
- **严格请求体解析：** 限制请求体体积并拒绝任何未知的 JSON 字段。

## Web 访问网关隔离 {#gateway}

网关自身从不直接读写用户文件：在线终端、SFTP 与跨集群 `rsync` 全部以当前登录用户的身份通过 SSH 执行，完全遵循操作系统的 Unix 权限控制。网关票据明确绑定用户、集群、权限范围与目标集群，每次请求均逐项核验。
